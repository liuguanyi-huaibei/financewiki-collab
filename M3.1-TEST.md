# FinanceWiki M3.1-A — PC1/PC2 多文档会话测试

Build: 0.3.0-dev.1  
Branch: feature/m3-session-manager  
Purpose: validate the new SessionManager before it is installed into the main knowledge Vault.

## Safety rules

1. This is a development build, not a stable release. Test with the existing dedicated collaboration test folder or a separate test Vault.
2. Back up the test Markdown files on both devices before upgrading.
3. Fully exit Obsidian before replacing the plugin files.
4. Preserve data.json, IndexedDB, Workspace ID, collaboration folder, signaling URLs and room password.
5. Do not run Seed again on an already seeded note.
6. Do not rename, move or delete test files during this M3.1-A test. Those operations are not implemented in this slice.
7. Install the exact same 0.3.0-dev.1 package on PC1 and PC2.

## Upgrade

1. Back up the test notes on both devices.
2. Exit Obsidian completely.
3. Back up the current main.js, manifest.json and styles.css outside the Vault.
4. Extract this package and replace only those three files in .obsidian/plugins/financewiki-collab/.
5. Keep data.json and all IndexedDB data unchanged.
6. Start Obsidian and verify the plugin manifest shows 0.3.0-dev.1.
7. Open the existing Collab-Test folder. Do not re-seed existing documents.

## Test fixture

Create the same five relative Markdown paths on both devices under the configured collaboration folder:

- M3.1-Test/01-Overview.md
- M3.1-Test/02-Mechanism.md
- M3.1-Test/03-Methods.md
- M3.1-Test/04-Results.md
- M3.1-Test/05-Discussion.md

Use plain Markdown without YAML frontmatter. PC1 seeds each new fixture note exactly once. PC2 opens the same paths and must not run Seed.

## Acceptance tests

| ID | Test | Pass condition |
| --- | --- | --- |
| A1 | Open five notes on PC1 | Five distinct sessions appear; each has its own room ID |
| A2 | Open the same five notes on PC2 | Matching notes connect to the matching PC1 rooms |
| A3 | Edit different notes on each device | Updates arrive only in the corresponding document; no cross-document text |
| A4 | Edit the same note concurrently | Both devices converge to the same Yjs content |
| A5 | Open one note in two split panes | Both views share one session; editor lease count is 2 |
| A6 | Close one split pane | The remaining pane stays collaborative; lease count becomes 1 |
| A7 | Close the final view | Session becomes idle with lease count 0; IndexedDB remains intact |
| A8 | Reopen within 30 seconds | The existing session is reused and idle eviction is cancelled |
| A9 | Close all views and wait over 30 seconds | In-memory session is evicted; IndexedDB remains intact |
| A10 | Reopen after eviction | Local Yjs content restores and the same v0.2.3 room ID reconnects without Seed |
| A11 | Restart Obsidian on both devices | Opening the test notes recreates sessions and restores their local content |

## Diagnostic evidence

For each open note, record:

- room ID;
- session lifecycle (active / idle / closing);
- editor lease count;
- local IndexedDB state;
- WebRTC connected/pending peer counts;
- whether both devices show the same content.

During split-pane tests, lease count should equal the number of active editor views for that file. It is not a count of team members.

## Known limitations

- The manager is currently keyed by the existing path-derived room ID.
- DocumentRegistry and stable document IDs are not implemented yet.
- Rename/move continuity, file-tree synchronization, YAML frontmatter and attachments are not part of M3.1-A.
- A session being evicted means its in-memory Provider/Y.Doc is closed; it does not mean the document or IndexedDB data is deleted.

## Rollback

Exit Obsidian, restore the three backed-up plugin files, then reopen Obsidian. Keep data.json and IndexedDB untouched. No re-seed is required.
